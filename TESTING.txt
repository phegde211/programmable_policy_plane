PROGRAMMABLE POLICY PLANE - BUILD & TEST PROCEDURE
==================================================
Author   : Prabhat Hegde
Copyright: (c) 2026 Prabhat Hegde. All rights reserved.

Companion to README.md (the specification). This document covers
prerequisites, build, a reproducible test plan on a veth pair, and the
skeleton's deliberate limitations.


1. PREREQUISITES
================
  - Linux kernel >= 6.1 recommended (conntrack kfuncs need >= 5.19),
    with CONFIG_NF_CONNTRACK (and CONFIG_NF_CONNTRACK_MARK for connmark),
    BTF enabled (/sys/kernel/btf/vmlinux present).
  - clang/llvm >= 14, bpftool, libbpf (>= 1.0), libxdp (xdp-tools),
    libelf, zlib.
      Debian/Ubuntu: apt install clang llvm libbpf-dev libxdp-dev \
                     xdp-tools bpftool libelf-dev zlib1g-dev
  - Root privileges; bpffs mounted at /sys/fs/bpf (default on modern
    distributions).

Repository files:
    xdp_plane.bpf.c      kernel-side XDP program (CO-RE)
    xdpctl.c             user-space loader / control-plane skeleton
    Makefile
    (generated by make: vmlinux.h, xdp_plane.bpf.o, xdp_plane.skel.h)


2. BUILD
========
    make                      # vmlinux.h -> bpf.o -> skel.h -> xdpctl

Notes:
  - vmlinux.h is generated from the running kernel's BTF; it provides the
    CO-RE type definitions (struct nf_conn, bpf_sock_tuple, IPS_* enums).
  - If libxdp headers are not packaged on the distribution, build
    xdp-tools from source (github.com/xdp-project/xdp-tools).


3. TEST PLAN (veth pair + network namespace)
============================================
All commands as root.

3.1 Topology
------------
    ip netns add peer
    ip link add veth0 type veth peer name veth1
    ip link set veth1 netns peer
    ip addr add 10.0.0.1/24 dev veth0
    ip link set veth0 up
    ip netns exec peer ip addr add 10.0.0.2/24 dev veth1
    ip netns exec peer ip link set veth1 up

        [ netns "peer" ]                [ default netns ]
        veth1 10.0.0.2  <--- link --->  veth0 10.0.0.1
                                        ^ XDP program attaches here

3.2 T1 - load and observe misses (defer-up default)
---------------------------------------------------
    terminal-1:  ./xdpctl load veth0
    terminal-2:  ip netns exec peer ping -c 3 10.0.0.1        # works
                 ip netns exec peer bash -c \
                   'echo hi | nc -u -w1 10.0.0.1 9999'

    EXPECT: ping succeeds (ICMP passes the narrow pipeline); the UDP
    probe prints a MISS line in terminal-1 and still reaches the stack.
    `./xdpctl stats` shows the miss counter incrementing.
    (Verifies: miss => XDP_PASS, never drop on ambiguity.)

3.3 T2 - static blocklist drop
------------------------------
    ./xdpctl block 10.0.0.2 32
    ip netns exec peer ping -c 3 10.0.0.1

    EXPECT: ping now fails; `./xdpctl stats` shows drop_blocklist
    rising. Remove the entry to restore:
      bpftool map delete pinned /sys/fs/bpf/xdp_plane/blocklist \
          key hex 20 00 00 00 0a 00 00 02
    (Verifies: IP-level static deny before everything else.)

3.4 T3 - explicit deny signal (the "program a rule" path)
---------------------------------------------------------
    terminal-2:  ip netns exec peer bash -c \
                   'while true; do echo x | nc -u -p 5555 -w1 \
                    10.0.0.1 9999; sleep 1; done'
    terminal-3:  ./xdpctl deny 10.0.0.2 10.0.0.1 5555 9999 udp 30

    EXPECT: after the deny is installed, drop_deny increments once per
    second and terminal-1 stops printing MISS lines for that flow.
    After 30 s (TTL) the entry expires and MISS lines resume.
    (Verifies: decide-once / replay-many; TTL re-evaluation.)

3.5 T4 - rate limiting
----------------------
    Rebuild with a small budget (or set skel->rodata before load):
        rate_pps = 100, rate_burst = 100
    ip netns exec peer ping -f 10.0.0.1          # flood ping

    EXPECT: drop_rate climbs; the stack receives at most ~100 pps.
    (Verifies: XDP's own light state shields the stack.)

3.6 T5 (optional) - conntrack allow / steer
-------------------------------------------
    Requires CONFIG_NF_CONNTRACK(+MARK) and traffic that traverses
    netfilter so conntrack confirms (e.g., a TCP service on 10.0.0.1).
    To exercise the steer branch, set a connmark at flow setup:
        nft add table ip t
        nft add chain ip t c '{ type filter hook input priority 0 ; }'
        nft add rule  ip t c tcp dport 8080 ct mark set 0x01000001
    and map next-hop id 1 to an interface in the fwd DEVMAP (bpftool map
    update). Packet #2 onward of a confirmed, marked flow redirects at
    XDP (production would also rewrite MACs - see Section 4).

3.7 Cleanup
-----------
    Ctrl-C in terminal-1 (detaches the program)
    rm -rf /sys/fs/bpf/xdp_plane
    ip netns del peer
    ip link del veth0 2>/dev/null


4. SKELETON LIMITATIONS (deliberate; production TODO)
=====================================================
  - No MAC rewrite on redirect: real forwarding needs bpf_fib_lookup()
    plus Ethernet source/destination rewrite before XDP_REDIRECT.
  - IPv4 only; no VLAN tag parsing; no IP fragments or options beyond
    basic ihl handling.
  - NAT-translated flows: the conntrack tuple must be derived for the
    original direction; not handled here.
  - Token bucket has a benign cross-CPU race (approximate policing).
  - ct->mark read assumes CONFIG_NF_CONNTRACK_MARK; guard with
    bpf_core_field_exists() for portability.
  - The agent is a CLI stub; a real control plane bridges firewall
    verdicts (nflog/nfqueue/ct events) into the deny map automatically.
  - Audit path emits miss events only; truncated packet sampling and the
    audit connmark bit are left as an exercise of the same ringbuf.
